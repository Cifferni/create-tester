# create-tester 踩坑记录

> 面向测试人员/维护者的实战避坑清单。按"现象 → 原因 → 对策"组织。

## 一、文本定位的风险

**现象**:用例昨天还过,今天一堆"找不到元素"。往往是页面文案改了(按钮"保存"变"提交",提示"保存成功"变"已保存")。

**根因**:用 `getByText`/`getByRole(button, { name })` 定位依赖文案,文案一变,用例全挂。

**对策**
- **优先 `data-testid`**:让开发给关键可交互元素加 `data-testid`(改文案不失效),这是最稳的定位方式。
- 定位优先级:data-testid → role+name → css/class → **getByText 仅兜底**(且必须页面唯一)。
- 页面里重复文案(多个"编辑"按钮、多行"操作")会触发 **strict mode violation**(2 个元素匹配),先 `.first()` 或加父子容器缩小范围。
- 文案核对用 `browser_find` 确认唯一性,别靠肉眼猜。

## 二、AI 生成的局限

**现象**:AI 生成的 spec 偶尔:断言写错、选择器想当然、把"页面现状"当"预期"、跑起来语法错。

**根因**:AI 依据用例文档和页面快照自由发挥,不确定性高;复杂页面快照信息不全时容易瞎猜。

**对策**
- **断言依据 = test-cases/ 用例文档的"预期"列**,不是页面现状。页面与预期不符时报告"页面与用例预期不符"(可能是 bug),**不要改断言迁就页面**。
- 用 `convert_case` 结构化输出(操作从"操作"列、断言从"预期"列),减少 AI 自由猜测。
- 生成后 **esbuild 语法预检**(run_tests 自动做),语法错直接报,别让 Playwright 空跑。
- 大页面用 `browser_snapshot` 的 target 精准看局部,别让 AI 拿到被截断的快照瞎猜。
- 每个用例**必须有业务断言**(接口 code/字段/状态码,或页面 URL/文案/状态),禁止"只点不验"。

## 三、复杂页面稳定性

**现象**:用例偶发失败——点快了、loading 没结束、弹窗/iframe/shadowDom 定位不到、网络抖动。

**根因**:页面是异步渲染的,固定延时(waitForTimeout)在慢机器上必崩;iframe/shadowDom 里元素普通选择器够不着;遮挡元素点不到。

**对策**
- **禁止 `waitForTimeout`**(硬编码延时)。要等就用智能等待:元素 `waitForVisible` / 按钮可点 `waitForClickable` / 文案 `waitForText` / 跳转 `waitForURL`,等状态不等时间。
- **iframe**:定位前切进 iframe,如 `page.frameLocator('#iframe-id').getByRole(...)`。
- **shadowDom**:官方 MCP 的 snapshot 支持穿透,用它生成的选择器通常是有效的;别手写穿透 CSS。
- **遮挡/不可点**:按钮被 loading 遮罩盖住时先 `waitForClickable`,再点。
- 环境类失败(刷新不保持、没登录、数据没清理)不算 bug:`test.skip` + 说明即可,别硬改断言。

## 三.5 图标按钮定位(无文字/label 的元素)

**现象**:AI 用 `browser_run_code_unsafe` 手写 `button:has(svg path[d^="M320..."])` 定位纯图标按钮,结果 `boundingBox: Timeout 30000ms exceeded`(找不到元素)。

**根因**:靠 SVG `path` 的 `d` 属性特征定位是最脆的方式——图标库重绘/换 sprite 后 `d` 一变就全失效,且毫无语义可读;连续猜选择器、不重新看页面结构是 AI 的常见错误。

**对策**
- 首选:让被测应用给这类按钮加 `data-testid`(如 `data-testid="refresh-btn"`),一劳永逸。
- 次选:先用 `browser_snapshot` 看结构,找按钮的可访问名/`aria-label`/`title`,用官方 `browser_click` 或 `browser_find` 定位,别手写 CSS。
- 兜底:确实无名字时,退到稳定的容器 + `[role]`/class 组合,但**不用 SVG `d` 特征**。
- 纪律:定位失败时**先重新 `browser_snapshot` 看真实结构**,别拿旧快照/猜的选择器硬试。

## 四、数据与环境

**现象**:回归第二次跑就挂——上一轮造的数据没清,列表多了一条;或登录态过期。

**对策**
- 改数据类用例:**造数据 + 自我清理**;判断新增/删除用计数对比(namesBefore/namesAfter),别靠名字唯一。
- 需要干净环境的用例**先构造**(`env_reset`/清理数据),构造不了才 `test.skip`+说明。
- 登录态过期重登:auth.setup 会自动处理;验证码场景 `npm run login` 人工登一次。
- 多账号隔离用 `TESTER_ACCOUNT`,别共用一个 auth 文件互相覆盖。
